# 3단계. 추론 엔진 설치와 첫 실행

> "추론 엔진" = 모델 파일을 GPU에 올려 실제로 대화를 시켜주는 프로그램.
> 세 가지를 씁니다. 각자 잘하는 게 다릅니다.

| 엔진 | 잘하는 것 | 우리 용도 |
|---|---|---|
| **vLLM** | 여러 요청 동시 처리(에이전트/서비스), 속도 | **주력**. 3090 8장 텐서 병렬 |
| **llama.cpp** | GGUF 파일, 서로 다른 GPU 섞기, VRAM 유연 배분 | K-EXAONE 같은 GGUF 모델, 2080Ti 활용 |
| **TabbyAPI (ExLlama)** | 1인 사용 시 최고 속도, GPU별 용량 불균등 분할 | 선택사항 |

> 2026년 주의: TGI(HuggingFace)는 개발 중단·저장소 아카이브됨. 쓰지 마세요.
> Ollama는 편하지만 텐서 병렬이 없어 멀티GPU 속도를 못 냅니다. 이 장비에는 아깝습니다.

## 3-1. vLLM 설치 (주력 엔진)

```bash
# uv (빠른 파이썬 패키지 관리자) 설치
curl -LsSf https://astral.sh/uv/install.sh | sh
source ~/.bashrc

# vLLM 전용 가상환경
uv venv ~/vllm-env && source ~/vllm-env/bin/activate
uv pip install vllm --torch-backend=auto
```

### 첫 실행 — 작은 모델로 테스트

```bash
source ~/vllm-env/bin/activate
vllm serve Qwen/Qwen3-4B-Instruct-2507 --port 8000
```

다른 터미널에서 테스트:

```bash
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"Qwen/Qwen3-4B-Instruct-2507","messages":[{"role":"user","content":"안녕하세요"}]}'
```

한국어 대답이 나오면 성공입니다.

### 진짜 실행 — 큰 모델을 GPU 8장에 (A컴퓨터)

```bash
vllm serve QuantTrio/Qwen3-235B-A22B-Instruct-2507-AWQ \
  --tensor-parallel-size 8 \
  --gpu-memory-utilization 0.92 \
  --max-model-len 32768 \
  --host 0.0.0.0 --port 8000
```

옵션 설명:
- `--tensor-parallel-size 8`: 모델을 8장에 쪼개서 **동시에** 계산 (속도↑)
- `--gpu-memory-utilization 0.92`: VRAM의 92%까지 사용
- `--max-model-len 32768`: 최대 문맥 길이. 메모리 부족 에러가 나면 이 값을 줄이세요

### vLLM의 중요한 규칙 (모르면 고생하는 것)

1. **텐서 병렬 개수는 2, 4, 8만 안전합니다.** 모델의 어텐션 헤드 수가 나누어떨어져야 해서 6이나 7은 대부분 에러가 납니다.
   - GPU 7장이면 → `-tp 4`로 4장만 쓰거나, 8장을 채우세요. (B컴퓨터에 3090 7장이 되면 `-tp 4` + 남는 3장은 다른 모델)
   - 8장인데 -tp 8이 안 되는 모델이면 → `--tensor-parallel-size 4 --pipeline-parallel-size 2` (4×2=8장 사용)
2. **3090에서 FP8 모델**: 돌아가긴 하지만 weight-only 방식(Marlin 커널)입니다. AWQ 4bit가 3090에 가장 궁합이 좋습니다.
3. NCCL 관련 멈춤 현상이 있으면: `NCCL_P2P_DISABLE=1` 환경변수 + `--disable-custom-all-reduce` 옵션.
4. **3090 + 2080Ti 혼합 금지**: vLLM은 가장 낮은 카드(2080Ti, SM75) 기준으로 전체가 제한됩니다. `CUDA_VISIBLE_DEVICES`로 3090만 보이게 하세요:
   ```bash
   CUDA_VISIBLE_DEVICES=0,1,2,3 vllm serve ... -tp 4
   ```

## 3-2. llama.cpp 설치 (GGUF·혼합 GPU 담당)

```bash
sudo apt install -y cmake build-essential
git clone https://github.com/ggml-org/llama.cpp ~/llama.cpp
cd ~/llama.cpp
cmake -B build -DGGML_CUDA=ON
cmake --build build --config Release -j
```

### 실행 예 — 서로 다른 GPU 섞어 쓰기 (B컴퓨터: 3090×3 + 2080Ti×2)

```bash
~/llama.cpp/build/bin/llama-server \
  -m /models/gpt-oss-120b-Q4.gguf \
  -ngl 999 \
  --split-mode layer \
  --tensor-split 24,24,24,22,22 \
  --main-gpu 0 \
  -c 32768 -fa on \
  --host 0.0.0.0 --port 8080
```

옵션 설명:
- `-ngl 999`: 모든 레이어를 GPU에 (숫자만 크면 됨)
- `--split-mode layer`: 층별로 나눠 담기. **서로 다른 GPU를 섞을 때는 이것.** (row는 구식·비추천)
- `--tensor-split 24,24,24,22,22`: GPU별 VRAM 비율. 3090=24, 2080Ti=22
- `--main-gpu 0`: 대장 GPU는 3090으로
- `-fa on`: 플래시 어텐션 켜기

### llama.cpp의 특성 이해

- 레이어 분할은 GPU가 **한 장씩 차례로** 일합니다. → GPU를 늘려도 속도는 안 늘고 **용량만** 늡니다.
- 그래서 llama.cpp에서는 **MoE 모델**(전문가 혼합: 전체는 크지만 매 토큰마다 일부만 계산)이 좋습니다. K-EXAONE-236B, Qwen3-235B 같은 것들이 MoE입니다.
- OCuLink/M.2로 x4에 연결된 GPU도 layer 분할에서는 손해가 거의 없습니다.

## 3-3. TabbyAPI + ExLlama (선택사항: 혼자 쓸 때 최고 속도)

```bash
git clone https://github.com/theroyallab/tabbyAPI ~/tabbyAPI
cd ~/tabbyAPI && ./start.sh
```

`config.yml`에서 GPU별 용량을 GB 단위로 마음대로 배분할 수 있는 게 장점입니다:

```yaml
model:
  model_dir: /models
  model_name: Qwen3-235B-exl3-3.0bpw
  max_seq_len: 32768
  tensor_parallel: true
  gpu_split: [22, 22, 22, 22, 22, 22, 22, 22]   # 불균등 배분 가능
  cache_mode: Q8    # KV캐시 압축으로 문맥 길이 2배
```

주의: 최신 ExLlamaV3는 2080Ti(Turing)를 사실상 지원하지 않습니다. 2080Ti는 llama.cpp 담당으로.

## 3-4. 예상 속도 (커뮤니티 실측 기준)

| 구성 | 모델 | 속도 |
|---|---|---|
| 3090×2, vLLM TP2 | 32B급 | 튜닝 시 60+ 토큰/초 |
| 3090×4, vLLM TP4, 220W 제한 | QwQ-32B | 약 39 토큰/초 |
| 3090×8, vLLM TP8 | 70B, 50명 동시 | 합계 800+ 토큰/초 |
| 3090×3, llama.cpp | gpt-oss-120b (MoE) | 41~73 토큰/초 |
| 3090×2, llama.cpp | GLM-4.5-Air (MoE) | 20~30 토큰/초 |
| 3090×8 예상 | Qwen3-235B AWQ TP8 | 단일 스트림 약 20~45 토큰/초 (추정) |
