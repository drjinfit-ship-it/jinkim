# 4단계. 모델 선택 — 무엇을 받아서 어디에 올릴까 (2026년 7월 기준)

> 핵심 결론부터:
> 1. 이 장비에서는 **MoE(전문가 혼합) 모델이 정답**입니다. 덩치는 크지만 매 토큰마다 일부만 계산해서 3~5배 빠릅니다. 192GB VRAM은 딱 MoE를 위한 구성입니다.
> 2. 한국어 최강은 **K-EXAONE-236B-A23B** (LG AI연구원, 2025년 12월 공개, **상업이용 가능**).
> 3. 범용 지능 대비 용량 효율은 **Qwen3-235B / Qwen3.5** 계열.

## 4-1. 왜 MoE인가 (쉬운 설명)

- 일반(dense) 70B 모델: 토큰 하나 만들 때마다 40GB 무게 전체를 읽음 → 3090 한 장 대역폭으론 십몇 토큰/초가 한계. GPU를 늘려도 층별 분할은 순서대로 일해서 안 빨라짐.
- MoE 235B-A22B 모델: 전체 무게는 130GB지만 토큰마다 22B(약 13GB)만 읽음 → **훨씬 크고 똑똑한 모델이 오히려 더 빠름.**
- 우리 장비 = VRAM은 많고(192GB) 장당 대역폭은 보통 → MoE에 최적.

## 4-2. A컴퓨터 (8×3090, 192GB) — "두뇌" 모델 1개

### 1순위: K-EXAONE-236B-A23B (한국어 최강)

- LG AI연구원의 한국 대표 모델. KMMLU-Pro 등 한국어 벤치마크 최상위, 256K 문맥.
- **K-EXAONE 라이선스: 상업이용 허용** (구형 EXAONE 4.0은 비상업이니 헷갈리지 말 것!)
- 공식 GGUF Q4_K_M = **143GB** → 192GB에 올리고 40GB가 문맥용으로 남음. llama.cpp로 실행.
- 받기: `hf download LGAI-EXAONE/K-EXAONE-236B-A23B-GGUF --local-dir /models/k-exaone-236b`
- 법률 문서·정책자금 서류 등 **한국어 공문서 작업이 주력이면 이걸 선택**하세요.

### 2순위: Qwen3-235B-A22B-Instruct-2507 AWQ (에이전트/서비스용)

- 범용 지능·코딩·에이전트 능력 최상급, 한국어도 준수(단, 문화적 뉘앙스는 K-EXAONE보다 약함).
- AWQ 4bit ≈ 125~133GB → vLLM TP8로 실행(3장 문서의 명령 그대로). 동시 요청 처리가 강해서 **여러 에이전트를 동시에 돌리는 자동화 시스템에 유리**.

### 참고: 안 되는 것들 (시간 낭비 방지)

| 모델 | 이유 |
|---|---|
| DeepSeek-R1/V3 (671B) | 1~2bit로 구겨 넣어야만 들어감 → 품질 하락, 비추천 |
| GLM-4.7/4.6 (355B) | Q4가 200GB+ → 192GB에 안 들어감 (EXL3 4bpw ~177GB는 아슬아슬하게 가능) |
| Mistral Large 3, Kimi K2 | 너무 큼 |
| 순수 dense 70B급 | 들어가긴 하지만 MoE보다 느리고 덜 똑똑함 |

## 4-3. B컴퓨터 (7×3090 + 2080Ti×2) — "보조 서비스" 모음

### 3090 그룹 (중형 모델 1~2개)

| 후보 | 크기(Q4) | 특징 |
|---|---|---|
| **Solar-Open-100B** (업스테이지) | ~60GB | **한국 법률·금융·의료 데이터로 학습** → 법률/정책자금 문서에 직격 |
| GLM-4.5-Air (106B-A12B) | ~63GB | 균형 좋은 만능형, 2×3090에서도 20~30 토큰/초 |
| gpt-oss-120b | 65GB | 3×3090에서 41~73 토큰/초로 매우 빠름. 한국어는 보통 |
| Qwen3.5-122B-A10B | 74GB | 이미지도 이해하는 멀티모달, 262K 문맥 |
| Qwen3-VL-30B-A3B | ~18GB | 문서 사진/스캔 OCR용 비전 모델 |
| HyperCLOVA X SEED Think-32B (네이버) | ~20GB | 작지만 에이전트 성능 우수, 한국어 강함 |

### 2080Ti 22GB × 2장 그룹 (상시 대기 서비스 — 이 카드들의 최적 용도)

| 서비스 | 모델 | VRAM |
|---|---|---|
| 음성→글자 (워치/Rokid 녹음) | faster-whisper large-v3 INT8 (+ 한국어 파인튜닝판: ghost613/whisper-large-v3-turbo-korean) | ~2~5GB |
| RAG 임베딩 (트레이닝 암묵지 검색) | Qwen3-Embedding-8B Q8 또는 BGE-M3 | 5~10GB |
| RAG 리랭커 | bge-reranker-v2-m3 또는 Qwen3-Reranker-4B | ~2GB |
| 문서 OCR | PaddleOCR-VL (0.9B) | ~4GB |
| 한국어 음성합성(TTS) | Supertonic / MeloTTS-Korean (CPU도 가능) / GPT-SoVITS | 0~4GB |
| 한국어 음성 올인원 | HyperCLOVAX-SEED-Omni-8B (한국어 STT+TTS 한 모델) | ~16GB |

## 4-4. 용량 계산법 (외우면 편한 공식)

- GGUF Q4_K_M ≈ 파라미터 수 × 0.6 바이트 (예: 235B → ~140GB)
- AWQ/GPTQ 4bit ≈ 파라미터 수 × 0.55 바이트
- 문맥(KV캐시): Qwen3-235B 기준 32K 문맥 ≈ 6GB, 128K ≈ 24GB (FP8 KV면 절반)
- 총합이 VRAM의 90%를 넘으면 문맥 길이를 줄이거나 KV 캐시를 Q8/FP8로 압축

## 추천 최종 배치 (요약)

```
A컴퓨터: K-EXAONE-236B Q4 (llama.cpp)   ← 한국어 문서·상담 두뇌
         또는 Qwen3-235B AWQ (vLLM TP8) ← 에이전트 자동화 두뇌

B컴퓨터: [3090들] Solar-Open-100B(법률/정책자금) + Qwen3-VL-30B(문서 OCR)
         [2080Ti들] Whisper(음성) + 임베딩/리랭커(RAG) + TTS
```

두 컴퓨터의 모델을 바꿔가며 A/B 테스트해 보고 업무에 맞는 조합을 찾으면 됩니다.
