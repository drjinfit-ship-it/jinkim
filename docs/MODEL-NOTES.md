# 모델 선정 메모 — M2 Max / 32GB 기준

## 확인 필요: "퀸 3.8"

말씀하신 모델명이 아래 중 무엇인지 확정이 필요합니다. 셋 다 실행은 가능하지만
메모리·속도·품질이 크게 다릅니다.

| 후보 | 4bit 가중치 | 실사용 RAM(ctx 8K) | 32GB에서 상시 상주 | 비고 |
|---|---|---|---|---|
| **Qwen3 8B** | 약 4.5–5 GB | 약 7–9 GB | ✅ 매우 여유 | "3.8" = 3세대 8B 로 해석 시 |
| **Qwen3 4B** | 약 2.5 GB | 약 4–5 GB | ✅ 극히 가벼움 | 보조 에이전트용 |
| **Qwen3 30B-A3B** (MoE) | 약 17–18 GB | 약 20–23 GB | △ 가능하나 빡빡 | 활성 파라미터 3B라 **8B보다 빠르면서 품질은 훨씬 높음** |

### 권장 구성 (2단 운영)

- **상시 상주 = Qwen3 8B 4bit** — 항상 떠 있는 [마이]의 기본 두뇌. 응답 즉시성 확보.
- **온디맨드 = Qwen3 30B-A3B 4bit** — 긴 문서·복잡한 추론이 필요할 때만 로드.
  MoE라 32GB에서 실용 속도가 나옵니다. 단, 이때는 8B를 언로드하는 정책 필요.

## 32GB 통합메모리 튜닝

macOS는 기본적으로 GPU에 할당 가능한 wired 메모리를 전체의 약 75%로 제한합니다.
큰 모델을 올릴 때만 다음으로 상향하세요 (재부팅 시 초기화, 영구 적용은 비권장).

```bash
# 32GB 중 26GB까지 GPU wired 허용 (30B-A3B 로드용)
sudo sysctl iogpu.wired_limit_mb=26624
# 원복
sudo sysctl iogpu.wired_limit_mb=0
```

> ⚠️ 시스템 여유를 6GB 미만으로 남기면 커널 패닉/강제 스왑이 발생합니다.
> 8B만 쓸 거면 이 설정은 **건드리지 마세요.**

## 양자화 선택

| 포맷 | 용도 |
|---|---|
| `Q4_K_M` (GGUF) | llama.cpp/Ollama 표준. 품질/용량 균형 최적 |
| `4bit` (MLX) | MLX 런타임용. Apple Silicon에서 대체로 더 빠름 |
| `Q5_K_M` | 32GB면 8B급은 이쪽도 충분. 품질 소폭 상승 |

## 모델 파일 지정

런타임/프롬프트와 모델은 완전히 분리되어 있습니다.
어떤 가중치를 쓸지는 `config/mai.env` 의 두 줄만 바꾸면 됩니다.

```bash
MAI_MODEL_ID="<허깅페이스 repo 또는 ollama 태그>"
MAI_MODEL_FILE="<GGUF 파일명 — MLX 사용 시 비움>"
```

즉, 어떤 파인튜닝/변형 가중치를 선택하든 세팅 구조는 그대로 재사용됩니다.
선택과 그 사용에 대한 책임은 로컬 운영자에게 있습니다.
