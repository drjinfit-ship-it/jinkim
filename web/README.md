# JIN.AI 라이브 리셋 — 웹 강의 시스템 (5부위 사전/사후 QR 측정 + 실시간 결과 보드)

법원·공공기관 50분 실습 강의를 위한 단일 HTML 앱입니다. 발표 화면(빔)과 참가자 화면(휴대폰)이 한 파일에 들어 있고, 수집 서버는 Google 스프레드시트 + Apps Script(무료)입니다.

| 구성 | 파일 | 역할 |
|---|---|---|
| 발표·참가자 화면 | `web/index.html` | 22장 슬라이드, 10개 QR(5부위 × 사전/사후), 실시간 평균·개선율 보드, 피날레, D+1 리포트 |
| 소스 | `web/src/app.html`, `web/src/qr-bundle.js`, `web/build.js` | 수정은 `src/app.html`에서 하고 `node build.js`로 `index.html` 재생성 |
| 수집 서버 | `web/backend/Code.gs` | Google Apps Script 웹 앱. 익명 응답을 시트에 저장하고 세션별 원자료를 JSON으로 반환 |

## 왜 claude.ai 아티팩트가 아니라 GitHub Pages인가

claude.ai 아티팩트는 데이터 저장 기능을 켜면 **조직 내부 로그인 사용자만** 접근할 수 있고, 외부 서버로의 전송도 차단됩니다. 법원 참가자가 휴대폰으로 익명 제출하려면 공개 주소가 필요하므로 GitHub Pages + Apps Script로 운영합니다. 아티팩트 버전은 같은 화면을 **데모 데이터**로 보여주는 미리보기입니다.

## 1. 배포 (총 15분)

### 1-1. GitHub Pages (발표·참가자 페이지 공개)
1. GitHub 저장소 → Settings → Pages → Source: **Deploy from a branch** → Branch: `main` (또는 이 브랜치) / 폴더 `/ (root)` → Save
2. 1~2분 뒤 주소가 생깁니다: `https://drjinfit-ship-it.github.io/jinkim/web/`
3. 그 주소를 열면 발표 화면이 뜹니다. 참가자 QR은 자동으로 같은 주소 + `?mode=join&s=세션&p=부위&t=pre|post` 로 만들어집니다.

### 1-2. Google Apps Script (익명 수집 서버)
1. Google 스프레드시트 새로 만들기 (이름 예: `JINAI_LIVE_RESET_DATA`)
2. 확장 프로그램 → Apps Script → `Code.gs` 내용을 `web/backend/Code.gs`로 교체 → 저장
3. 배포 → 새 배포 → 유형 **웹 앱** → "다음 사용자 인증 정보로 실행: 나" / "액세스 권한: **모든 사용자**" → 배포 (권한 승인 1회)
4. 나온 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`)을 복사
5. 발표 화면에서 `S` 키 → 백엔드 URL에 붙여넣기 → **연결 테스트** → 저장. 데모 모드 체크 해제.

코드를 고치면 "배포 관리 → 새 버전"으로 갱신해야 URL에 반영됩니다.

## 2. 강의 당일 운영

| 시점 | 할 일 |
|---|---|
| 전날 | 발표 노트북에서 Pages 주소 열기 → `S` 설정에서 세션 코드(예 `suwon-2`)·표시명 입력 → 휴대폰으로 사전 QR 1개 찍어 제출 테스트 → `R` 리포트에서 1건 보이는지 확인 → 테스트 행은 시트에서 삭제 |
| 시작 직전 | `F` 전체화면, `T` 타이머 시작(첫 슬라이드에서 → 를 누르면 자동 시작), `N` 강사 노트 |
| 각 부위 | 사전 QR(1.5분) → 실습(5분) → 사후 QR(1.5분). QR 화면은 5초마다 자동 갱신되어 응답 수·평균·감소폭이 올라갑니다 |
| 피날레 | "결과 공개" 버튼 → 참여자 수, 개선 비율, 평균 감소, 2점 이상 감소 비율, 부위별 표가 애니메이션으로 공개 |
| 종료 후 | `R` → 리포트 복사 → D+1 기관 리포트에 붙여넣기. 원자료는 시트 `responses`에 보존 |

키: `→` 다음 · `←` 이전 · `S` 설정 · `N` 노트 · `R` 리포트 · `M` 수기 집계 · `F` 전체화면 · `T` 타이머 재시작 · `Esc` 닫기

### 와이파이·QR이 안 될 때 (플랜 B)
사후 QR 슬라이드에서 `M` → 손들기로 "변화 없음 / 1점 / 2점 / 3점 이상 감소 / 증가" 인원을 입력하면 그 부위의 전후 데이터로 피날레·리포트에 반영됩니다(수기 표시 `*`). 종이 0~10 카드를 준비해 두면 사전·사후를 손으로도 받을 수 있습니다.

## 3. 데이터·증빙 구조

| 항목 | 내용 |
|---|---|
| 저장 항목 | 시각, 세션코드, 익명 토큰(기기별 무작위 12자), 부위, 사전/사후, 점수 0~10, 선택 응답(업무 방해 1~5, 연령대, 느낌 변화) |
| 받지 않는 것 | 이름, 연락처, 소속, 직급, 휴대폰 뒷자리, 사진 |
| 짝짓기 | 같은 기기의 토큰으로 사전·사후를 매칭. 매칭 안 된 응답은 평균에만 포함, 개선율에는 제외 |
| 지표 | 부위별 사전/사후 평균, 평균 감소, 1점·2점 이상 개선 비율, 변화 없음·증가 비율, 전체 전후 응답 쌍 수, 1개 부위 이상 개선된 참여자 비율 |
| 공개 기준 | 설정의 "최소 N"(기본 5) 미만이면 화면에 "참고용" 표시. 리포트에는 항상 N 병기 |
| 한계 문구 | 화면·리포트·참가자 페이지에 자동 표기: 교육 직후 익명 자기보고, 대조군 없음, 의학적 효과 아님 |

기관 간 비교·차수별 개선 증빙은 세션 코드(`suwon-1`, `suwon-2`, `hanwha-3` …)로 구분된 시트 원자료로 합니다. `?action=sessions` 로 세션 목록을 받을 수 있습니다.

## 4. 개인정보·청렴 관련 설계

- 참가자 페이지에 "이름·연락처·소속을 받지 않으며 개인 결과는 기관에 전달되지 않는다"를 명시했습니다. 서버 접속 로그는 Google 인프라가 기술적으로 처리할 수 있으므로 "전혀 수집하지 않는다"고 말하지 않습니다.
- 마지막 화면의 후속 프로그램 안내는 개인 신청 QR이 아니라 **기관 공식 안내**로 동일 조건 제공을 원칙으로 합니다. 현장에서 개인 연락처를 받지 않습니다.
- 사진 촬영은 동의 후 진행하고, 기관명·사진·결과의 대외 사용은 기관 서면 승인 후에만 합니다.

## 5. 수정 방법
```bash
# 슬라이드 문구·부위 내용은 web/src/app.html 의 PARTS / R 객체에서 수정
cd web && node build.js
```
